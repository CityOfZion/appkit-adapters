# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this app. See the root `CLAUDE.md` for monorepo context and the adapter architecture.

## App

Connect Lab — WalletConnect V2 testing UI for Neo3, NeoX, Stellar, Bitcoin, Solana and EVM chains. React 19 + Vite + TanStack Router (file-based) + Tailwind v4 + shadcn/ui. Live at https://cityofzion.github.io/appkit-adapters/.

## Setup & commands

This app is **outside Rush** — use `pnpm` from this directory. It consumes the local packages via `file:` deps, so they must be built first:

```bash
# from repo root
rush install && rush rebuild
# then here
pnpm install          # re-run after rebuilding packages to pick up new dist/
pnpm run dev          # vite --force → http://localhost:5173/appkit-adapters/
pnpm run build        # vite build && tsc
pnpm run typecheck
pnpm run lint         # eslint .
pnpm run format       # prettier --write .
pnpm run check        # prettier --write . && eslint --fix
```

Requires `VITE_PROJECT_ID` (Reown project id) in `.env`.

## Architecture

- `src/helpers/chain.tsx` — `ChainHelper.chainInfos`: single registry of supported chains (name, color, icon, namespace, networks, explorer URL templates keyed by network id). Several "chains" share the `eip155` namespace.
- `src/helpers/appkit.ts` — `AppKitHelper.setup(chain)` calls `createAppKit` with **only** the selected chain's adapter, networks and `OVERRIDES` (adapters are static instances; `getAdapter` maps namespace → adapter). The chain is persisted in `localStorage` (`connect-lab:chain`) and `routes/__root.tsx` boots AppKit with it so sessions restore. AppKit is a singleton (global controllers, no runtime add/remove of adapters), so selecting a different chain after init reloads the page into `/connect`.
- `src/contexts/connection.tsx` — exposes `selectedChain`, `selectChain(chain)`, `connect()` (opens the modal for the selected chain) and `disconnect()`. AppKit hooks throw before `createAppKit`, so they live in `AppKitConnectionSync` (renders `null`, sibling of `children` so the tree isn't remounted when AppKit initializes); it derives `TConnectionInfo` from `useAppKitAccount().caipAddress` by matching namespace + network id against `chainInfos`; disconnects if no match. Has a deliberate 2s delay on first render (only when booting with a stored chain) to avoid flashing the landing page during reconnect.
- `src/contexts/request.tsx` — `request(method, call)` wrapper that drives the global request/result modal state.
- `src/routes/` — `index.tsx` (chain picker), `connect.tsx` (selected chain + Connect / Change network buttons) and `connected/route.tsx` (account info + method cards). Files prefixed with `-` are colocated components ignored by the router. `src/routeTree.gen.ts` is generated by the router plugin; don't edit it.
- `src/components/methods/*-methods.tsx` — per-chain demo actions. Neo3, Stellar, Bitcoin and Solana use `useAppKitProvider<XProvider>(namespace)`; EIP-155 uses `@wagmi/core` actions with `AppKitHelper.eip155Adapter.wagmiConfig`, and NeoX uses the neox-adapter's `sendTransaction` / `signTransaction` (plain) and `sendAntiMevTransaction` / `signAntiMevTransaction` (anti-MEV envelope), each with its own card. Mapping chain → component is `methodsComponentByChain` in `routes/connected/route.tsx` (kept there for fast-refresh reasons).
- `src/components/ui/` — shadcn/ui components (`components.json`). Radix primitives come from the `radix-ui` umbrella package (e.g. `import { Dialog } from 'radix-ui'`), not individual `@radix-ui/react-*` packages. Class merging is `StyleHelper.merge` (`src/helpers/style.ts`), not shadcn's `cn`.

### Adding a chain

Add icon in `src/assets/icons/`, entry in `ChainHelper.chainInfos` (+ `TSupportedChain`), a static adapter in `AppKitHelper` + its case in `AppKitHelper.getAdapter` (with overrides), a methods component, and the `methodsComponentByChain` entry.

## Gotchas

- Base path `/appkit-adapters/` is set in both `vite.config.ts` (`base`) and `src/main.tsx` (router `basepath`); change both together.
- `@reown/appkit` is patched by pnpm itself (`patches/@reown__appkit.patch`, registered in `pnpm-workspace.yaml` `patchedDependencies`; no `patch-package`) so network restoration matches by `caipNetworkId` instead of bare `chainId` — needed because Neo3 and Stellar both use id `testnet`. The patch key and every `@reown/*` dependency are pinned to the same exact version (`1.8.18`; Reown packages must stay on one release): to upgrade, bump them all together, regenerate the patch (`pnpm patch @reown/appkit@<version>` → `pnpm patch-commit`), and commit the updated `pnpm-lock.yaml`.
- Each EVM chain has its own static `WagmiAdapter` (`AppKitHelper.eip155Adapter` is a getter for the initialized one). Don't share one adapter across EVM chains: if the wagmi config chains differ from the networks passed to `createAppKit`, wagmi's WalletConnect connector flags the session as stale (`isChainsStale`) on reload and disconnects it.
- `pnpm-workspace.yaml` lists which dependency install scripts run (`onlyBuiltDependencies`) or are skipped (`ignoredBuiltDependencies`); classify any new one there instead of leaving the `pnpm approve-builds` warning.
- The app is dark-only (`class="dark"` on `<body>` in `index.html`); there is no theme provider.
- There is no global `Buffer` polyfill. Import it explicitly from the npm package: `import { Buffer } from 'buffer'`. Never `node:buffer` — Vite stubs Node built-ins as empty modules in the browser. `node/prefer-node-protocol` is off for `src/**` in `eslint.config.js` so `eslint --fix` doesn't rewrite it.
- Path alias `@/` → `src/`. SVGs imported as components with `?react` (vite-plugin-svgr).
- Vite 8 (Rolldown). React Compiler is enabled through `@rolldown/plugin-babel` with `reactCompilerPreset()` from `@vitejs/plugin-react` (v6 dropped the `babel` option); avoid manual memoization patterns that fight it.
- Style: Prettier with single quotes, no semicolons, 120 columns, tailwind class sorting. `src/routeTree.gen.ts` is excluded via `.prettierignore`.
- `tsconfig.json` has `allowJs` so the type-aware ESLint config can parse `eslint.config.js` / `prettier.config.js`.
